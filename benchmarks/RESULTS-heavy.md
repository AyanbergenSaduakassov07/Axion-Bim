## Notes (2026-11-11)

Models: buildingSMART public samples (Clinic Architectural r1 and revB, Clinic Structural, Clinic HVAC,
Schependomlaan, Chesapeake Bay Bridge-Tunnel, Infra-Bridge); CC-BY, not committed (docs/release-check.md row 14).
Together 7 models, 30,000+ elements, 2 MB to 49 MB, IFC2X3, IFC4 and IFC4X3.

- **No crashes, timeouts or BCF failures.** Every model went through ingest, audit with IDS, gate, the geometry
  pass, and HTML + BCF export. Every BCF is a valid zip. The 49 MB Schependomlaan file takes 12.6 s end to
  end. Chesapeake (17,553 elements) takes 24.5 s with the geometry pass. Peak memory stays under 1.7 GB,
  far below the job runner's 8 GB limit.
- **Real revision pair:** `axiom compare Clinic_Architectural.ifc Clinic_Architectural_revB.ifc` took 8.2 s
  for two ingests, two audits and the comparison. It found 25 walls removed and 25 elements modified,
  giving 50 resolved findings (element removed) and 4,202 persistent, with MHI 89.26 → 89.30. This matches
  the earlier result in D-29.
- **Chesapeake: every check passes, 0 fail and 0 warning.** This is genuine, not a missing evaluation. An
  independent ifcopenshell count over all 17,553 elements finds 0 without classification and 0 without
  base quantities. The 75 elements without material are 71 IfcVehicle and 4 IfcUnitaryEquipment, which
  MAT-001 does not check. The model is 25 km long, and GEO-003 (D-47) raised no false far-element
  warnings on it.
- **Clinic HVAC: MHI 100 with 1,548 classification warnings.** All the IfcFlowSegment pipes and ducts carry
  no classification reference. A warning counts toward coverage but not toward the score (D-15),
  so classification_quality is 2156/2156 = 100. The gate shows *accepted with comments* and lists them.
  This is by design, but a reviewer reading only the MHI would miss it.
- **Clinic Structural: rejected.** It has 1,632 fails, mostly missing base quantities and materials on
  structural elements (MHI 76.0).
- **The IDS file `structural-basic.ids` is not applicable to these models.** Its exact-class facets do not
  match them, so the ids_compliance dimension is not evaluated and its weight is redistributed. A real
  project needs the client's own IDS.
- **Fixed during this run:** a null-content model reply crashed the copilot (now an empty answer), and a single provider 503 aborted the whole live copilot eval (now skips
  that case as *not run*). See D-48.
