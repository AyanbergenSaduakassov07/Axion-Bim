# Decisions (ADR log)

Append-only. One entry per decision: context → decision → consequence. Supersede, don't edit.

## D-01 Library + CLI before API/UI
Engine is `src/axiom`, exercised first through `axiom` CLI. API and web call the same `services/`. Consequence: every feature is testable without HTTP or a browser; demo exists from M1.

## D-02 Python 3.12, uv, one package
ifcopenshell 0.9.0 supports 3.10–3.15; 3.12 is the safe wheel target. One package `axiom` with modules; no workspace until a second consumer exists.

## D-03 Revision diff = snapshot diff
Diff normalized snapshots by GlobalId (added / removed / modified, property-level paths like `pset:Pset_ColumnCommon.LoadBearing`). IfcDiff (0.9.0) is optional cross-check and geometry-change signal only. Consequence: fast, deterministic, granularity matches findings.

## D-04 IDS for information requirements; Python rules for the rest
IfcTester 0.9.0 evaluates IDS. Custom rules are Python functions registered with metadata (id, version, name, category, severity, dimension, applicability, issue_key). No YAML DSL. Rule parameters (thresholds) may live in a small YAML per rule set. Both produce `Finding`.

## D-05 SQLite via SQLAlchemy Core + Alembic
Postgres later is a URL change. JSON columns only for evidence/metadata. All queries parameterized; repo layer only, called from services only.

## D-06 Subprocess job runner, no Redis
Jobs table in SQLite; runner spawns a child process per job with timeout and memory limit (`resource.setrlimit` on POSIX). Reason: isolate native crashes, not scale. Swap to RQ/arq only when concurrency demands it.

## D-07 Fixtures generated by code
`tests/fixtures/factory.py` builds IFC4 models with `ifcopenshell.api`, each with an `expected.yaml`. Public models only for benchmarks; record license + source in `examples/models/SOURCES.md`.

## D-08 Viewer: ThatOpen components 3.x (pending P00)
Pin `@thatopen/components`, `components-front`, `fragments` at the versions P00 validates (3.6.x as of 2026-11-09), `web-ifc` 0.0.77 (see D-11). Backend stays the source of truth; viewer only renders and maps GlobalId ↔ local id. Fallback if P00 fails: xeokit-sdk (AGPL — check license impact) or web-ifc + three.js direct.

## D-09 Copilot: read-only tools over services, citation post-check
Claude tool-use; tools wrap service functions, never raw SQL. Every GlobalId / finding id in the final answer must appear in that turn's tool results, else reject. Source IFC never sent to the LLM.

## D-10 Reports: JSON canonical, HTML rendered, PDF = browser print
Every report embeds reproducibility block: file sha256, ruleset hash, IDS hash, engine + app version, scoring config, timestamp.

## D-11 Viewer pins validated (amends D-08) — 2026-11-09
P00 GO for ThatOpen. Pins: three 0.182.0, @thatopen/components 3.6.0, @thatopen/fragments 3.6.1, **web-ifc 0.0.77** (0.0.78 incompatible with fragments 3.6.1). WASM + fragments worker served from our own origin. Element table stores `step_id` (== viewer localId) alongside GlobalId to disambiguate duplicate GlobalIds.

## D-12 New candidate rule QTO-002 + IDS coverage hints — 2026-11-09
From P00: Revit-exported Qto values can be off by unit factors (slab GrossVolume ×1000). Add QTO-002 (Qto vs geometry/declared-dimension plausibility) in P07. IDS adapter reports subtype coverage gaps (exact-class entity facet) and maps zero-applicable specs to `not_applicable`.

## D-13 Snapshot storage details — 2026-11-09
Property values stored typed (`value_type` + `value_text`/`value_num`), not JSON, so rules and SQL compare natively; `load_snapshot(ingest(x)) == extract(x)` is a test invariant. Revisions are unique per (model, file sha256) and numbered `seq` per model. Openings/voids (IfcFeatureElementSubtraction) are excluded from elements. Profile treats material as expected only on primary structural classes; rule sets own the real applicability (P03).

## D-14 IDS adapter mapping — 2026-11-09
- One IDS spec = one rule `IDS:<identifier or name>`, version = IDS file sha256[:12]; counts are per (applicable entity, requirement facet). Duplicate ids get `#<spec index>`.
- Status: spec for another schema -> `not_applicable` (`should_filter_version=True`); unevaluated -> `not_evaluated`; zero applicable -> `fail` if required (minOccurs>0) else `not_applicable`; prohibited (maxOccurs=0) -> one `fail` per matching entity.
- Severity per requirement facet: `optional` cardinality -> medium, else high. Coverage gaps (exact-class entity facet skipping subtypes, e.g. IfcWallStandardCase) -> `warning`/`info`, issue_key `<i>/coverage/subtypes`.
- IfcTester 0.9.0 drops spec `@identifier`; `load_ids` decodes once and restores it. It also fails the suite case "optional attribute passes if null"; we report its verdict unchanged and track it as a strict xfail.
- IDS files stored content-addressed next to IFCs (`files/<sha256>.ids`), hash in `audit_runs.ids_hash`. `ruleset_version` still identifies built-in rules only.
- Conformance subset: 13 buildingSMART IDS test cases vendored unmodified (CC BY-ND 4.0, attribution in NOTICE).

## D-15 MHI v1 scoring details — 2026-11-09
- Config `src/axiom/score/config/default.yaml` (versioned; stored per audit in `audit_runs.scoring_config_json`, version in the reproducibility block). Rule→dimension by fnmatch pattern, first match wins; unmapped rules are noted, not scored.
- `s_i = pass/(pass+fail)`. `warning` counts as evaluated for coverage but not in the score, so a model without classification gets a null `classification_quality` (noted, weight redistributed) rather than a fail. `not_applicable` is neither score nor coverage gap.
- Coverage = (pass+fail+warning)/(that + not_evaluated + error). IDS subtype coverage gaps (D-14) add one `not_evaluated` per skipped entity, so coverage drops instead of hiding them.
- Score rounded to 6 dp (float-sum noise); null when no dimension evaluated. Critical gate = any `critical` `fail` finding → `blocked`, identity keys listed.
- MET-001 (naming) and QTO-001 feed `property_completeness`; GEO-002 feeds `model_consistency`.

## D-16 · Revision engine details (P06)
- Diff matches by GlobalId; duplicated GlobalIds in either snapshot are excluded and listed as uncertain. Quantities compare on `si_value` with `QUANTITY_REL_TOL=1e-6`, so a unit change alone is no change. Removed property → `new=None`.
- `identity_unstable` when removed AND added both exceed 50% of a class in the base; then every event is `uncertain`.
- History = latest audit of every audited revision of the model up to base (by seq). `changed` = same identity key, different status/severity/actual/evidence.
- A rule run on only one side (e.g. IDS used in one audit) cannot resolve or introduce findings: its events are `uncertain` with note `rule_not_evaluated_in_base|head`. Ruleset/IDS hash mismatch is flagged in `comparisons.summary_json`.
- Impact = non-persistent events on elements that also changed, with the change paths. Not done: "rules whose applicability covers the changed element" (needs applicability introspection), `--ifcdiff` cross-check (optional).
- `axiom audit` auto-compares with the previous revision of the same `--model`; the default model name is the file stem, so differently named files are separate models unless `--model` is given.

## D-17 · Quantity intelligence details (P07)
- Totals keyed by (group, qto, quantity, method): two Qto sets never double-count and `qto`/`geometry` values are never summed (`method` is part of the row key; tested). Units are SI labels (m, m2, m3, kg) since `si_value` is already scaled at extraction.
- `missing` = GlobalIds in the group whose class carries that quantity elsewhere in the group but has no value; never treated as zero.
- `--geometry` computes volumes for every element (not only those lacking Qto) via `ifcopenshell.geom.iterator` + `util.shape.get_volume`, so Qto and geometry columns can be compared. Geometry area left out: the shape footprint is in local coordinates and would mislead.
- QTO-002 (D-12) = Qto Gross/NetVolume vs geometry volume, fail outside x2, hint when the ratio is ~1e3/1e6/1e9. Opt-in (`run_audit(geometry=True)`, `axiom audit --geometry`), recorded as `reproducibility.geometry`. Finds both x1000 slabs in the Revit sample. Comparing a geometry audit with a non-geometry one gives `uncertain` QTO-002 events (D-16).
- Revision deltas: `services.quantities.delta(base, head)` on grouped totals; not yet folded into `comparisons.summary_json` (P11 can call it).

## D-18 · API + job runner details (P08)
- Job kinds are an allowlist `kind -> "module:function"` (`services.jobs.KINDS`); the spawned child imports only that target. Tests add kinds (`tests/jobkinds.py`) through `create_app(kinds=...)`; nothing user-supplied ever names code.
- Child result/error comes back over a Pipe; `poll(timeout)` also returns on EOF, so a native crash is detected immediately, a hang at `AXIOM_JOB_TIMEOUT_S` (child killed). Messages are user-safe: `ValueError` text (our services' user-facing errors) or a generic line; tracebacks only in the log. `running` jobs at startup -> `error` ("server restarted").
- `RLIMIT_AS` is applied best-effort: macOS ignores/refuses it (logged at debug), Linux enforces it. The wall-clock timeout is the guard that always holds.
- Settings stay a frozen dataclass read from env (no pydantic-settings dependency); added `AXIOM_MAX_UPLOAD_MB`, `AXIOM_JOB_TIMEOUT_S`, `AXIOM_JOB_MEM_MB`.
- Upload intake (`services.uploads`): extension, size (streamed count, 413), `ISO-10303-21;` header, sha256 content address, then a `pipeline` job (ingest -> audit -> compare with previous). IDS uploads are XSD-validated in the request (XML only, no IFC) and referenced later by `ids_hash` (regex-checked, must exist).
- Quantities over HTTP are Qto-only; geometry volumes need IFC processing and stay in `axiom audit --geometry` until a job kind is needed (P11).
- Errors: `{error: {code, message}}` for 400/404/413/422/500; 422 lists field names, never echoes input.
- OpenAPI: `uv run python scripts/export_openapi.py` -> `apps/web/src/api/openapi.json`; P09 runs `npx openapi-typescript src/api/openapi.json -o src/api/schema.d.ts`.

## D-19 · Web shell + Quality Center (P09)
- `apps/web`: Vite 8, React 19, Tailwind 4 (`@theme` tokens in `src/index.css`, dark graphite default, light via `prefers-color-scheme`), TanStack Query + Virtual, React Router 8 (declarative mode). TypeScript is pinned to 5.9: TS 7 ships no JS compiler API, which openapi-typescript needs.
- Types come only from `src/api/schema.d.ts` (generated); `client.ts` adds hand types for the untyped `/audits/{id}` summary (`mhi`, `rules`). CI fails if `openapi.json` or `schema.d.ts` drift from the backend.
- No CORS on the API: the Vite dev proxy forwards `/api` (`AXIOM_API`, default :8000). Production serving is decided in P13.
- Findings are filtered/sorted client-side (one fetch per audit, immutable, `staleTime: Infinity`); the server filters stay for the CLI/copilot. Revisit when an audit exceeds ~50k findings.
- `not_evaluated` is drawn hatched grey with a dashed icon and never in a fail colour; severity and status always pair an icon with text.
- Smoke test: `npm run e2e` starts a fresh API (`apps/web/.e2e/`, gitignored) and Vite, uploads generated `rev1` + `structural-basic.ids`, asserts 4 findings and MHI 95.2. `AXIOM_SHOTS=<dir>` saves screenshots.

## D-20 · 3D viewer and Model Explorer (P10)
- `apps/web/src/viewer/` is the only code that imports ThatOpen/three. Its API speaks GlobalIds (`load`, `highlight(Map<colour, gids>)`, `focus → ok|no_geometry|not_found`, `isolate`, `setClassVisibility`, `onSelect`); localIds never leave the module.
- IFC → Fragments runs in a module web worker (`FRAGS.IfcImporter`). The result is cached in IndexedDB under `<file_sha256>:frag-<version>`; bump `FORMAT` in `cache.ts` with any fragments upgrade. Every cache call degrades to "no cache".
- The source IFC comes from `GET /revisions/{id}/file` (content-addressed, `immutable` cache header); the tree from `GET /revisions/{id}/tree`. The element panel uses `/elements/{gid}` plus the latest audit's findings, so the viewer never computes anything.
- web-ifc wasm and the fragments worker are copied from the pinned packages into gitignored `public/` by a Vite plugin in the `config` hook (before the dev server indexes `public/`). Never unpkg (D-08).
- `window.__axiomViewer` (`focus`, `lastFocused`, `stats`, `heapMB`) exists only in dev builds, for Playwright and measurements; disposing a viewer removes it.
- "Highlight in 3D" colours each element of the current filter by its worst non-pass severity, using the theme's severity tokens.

## D-21 · Reports + Revision Intelligence UI (P11)
- One canonical report dict (`services/reports.build`, `format: axiom-report/1`) rendered three ways: JSON, CSV (one row per finding), self-contained HTML (Jinja2, autoescape, inline CSS, `@media print`, no scripts or external URLs). PDF = browser print of the HTML.
- `POST /audits/{id}/reports?format=` renders on demand from stored results; nothing is stored, no IFC is opened. CLI `axiom report` uses the same service.
- Golden test (`tests/fixtures/expected/report_rev1_rev2.json`) masks only run-specific values (row ids, timestamps, file hash/size); `UPDATE_GOLDEN=1` regenerates. Rule ids and GlobalIds stay asserted.
- Revision page `/models/{id}/revisions?base=&head=`: uses the stored comparison when one exists, otherwise offers "Compare" (job). Uploads already compare with the previous revision.
- Comparison view: events ordered recurring → new → changed → uncertain → resolved, persistent collapsed; each event focuses its GlobalId in the head model. Removed elements are not drawn (no ghost of the base model); their count is shown.
- Identity-unstable comparisons hide per-element impact and property changes and show a banner; modified highlights are suppressed.
- MHI waterfall: base → dimension contribution changes ≥0.05 pt → re-weighting residual → head; withheld scores show a message, never a bar. Pure step math in `waterfall-steps.ts`, tested with `node --test` (no new dependency).
- Quantities page shows qto totals by class/storey/material/classification with Δ against the previous revision; method is always shown.

## D-22 · Grounded copilot (P12)
- Manual tool-use loop over the Anthropic SDK (`axiom/copilot/agent.py`), default `claude-sonnet-5-5` (`AXIOM_COPILOT_MODEL` overrides), max 8 tool rounds, system prompt cached. Key only from `ANTHROPIC_API_KEY`; none → `GET /copilot` reports `available: false`, `POST /copilot/query` returns 503 `copilot_unavailable`, and the web panel is not rendered. Everything else works.
- 9 strict, read-only tools over existing services (summary, elements, findings, comparisons, events, MHI, quantities). `project_id` comes from the session, never the model; a revision outside the project is "not found". Pages ≤50 rows.
- Tool results are sent as `{"note": …, "data": …}` JSON so IFC strings (names, descriptions) are data, never instructions. The injection fixture puts an instruction in a wall name.
- Citations use the markup `[[el:<GlobalId>]]` and `[[finding:<identity_key>]]`. Post-check: every marked id and every bare GUID-like or 40-hex token must have appeared in a tool result this turn. On failure the model gets one corrective retry; anything still unverified is stripped and listed in `unverified`. The UI turns verified ids into chips that open the Explorer (`?focus=`) or the Quality Center (`?finding=`) of the cited revision.
- Eval: `tests/copilot/evals.yaml` (25 cases: lookups, changes, events, MHI, quantities with unit + method, unanswerable, safety bait, injection), graded deterministically (tools called, ids cited, regex present/forbidden, zero unverified). `uv run python -m axiom.copilot.eval` is billed and runs only with a key; target ≥90% pass and 0 fabricated citations.
- Eval on free OpenRouter model (`nvidia/nemotron-3-ultra-550b-a55b:free`): 6 cases evaluated before daily limit (50 requests/day, HTTP 429). Score: 4/6 passed (67%), 0 fabricated citations (q01 pass, q02 pass, q03 pass, q04 fail [element citations], q05 fail [findings tool not called], q24 pass). Prompt tuned to explicitly guide missing properties/materials to `findings`.
- No auth or rate limit on `/copilot/query` (local-first, single user). Each call spends the key owner's money; add both before any shared deployment.

## D-23 · Dropped ifcdiff dependency (P13)
- `ifcdiff==0.9.0` was originally listed in D-03 as an optional cross-check and geometry-change signal.
- In practice, snapshot-based diffing (`axiom.revision.diff`) is pure Python/SQL, deterministic, and operates at the exact property and finding granularity needed for MHI and regression events.
- `ifcdiff` remained unused across all production and test modules, pulling in heavy dependencies (`deepdiff`, `orderly-set`, `cachebox`). Removed in P13 to reduce build time and attack surface.

## D-24 · Local-first hardening without auth (P13)
No auth by design, so the threat is a hostile web page in the user's own browser. Middleware in `api/app.py`:
`Host` must be in `AXIOM_ALLOWED_HOSTS` (stops DNS rebinding, which would make reads same-origin), and
non-GET requests carrying an `Origin` outside that list get 403 (stops blind cross-site uploads; CORS does
not cover simple multipart POSTs). Requests without `Origin` (curl, CLI) pass. IDS files with a DOCTYPE are
rejected before parsing: IDS needs no DTD, and xmlschema's default `defuse='remote'` still expands internal
entities. Docker API runs as uid 10001. Deferred: copilot rate limit, SPA CSP (viewer workers/wasm), disk quota.

## D-25 · BCF 3.0 export of open findings
`format=bcf` on the report route and CLI. One topic per `fail`/`warning` finding; `pass`, `not_applicable`,
`not_evaluated` are not issues. Topic GUID = uuid5(fixed namespace, finding `identity_key`), so a later
audit's export updates the same topics in a BCF tool instead of duplicating them (persistent findings keep
their identity key across revisions). Viewpoint selects the element by GlobalId; project-level findings
have no viewpoint. BCF 3.0 XSD requires a camera: it looks at the element's world placement origin
(`elements.origin_x/y/z`, migration 0005, extracted via `ifcopenshell.util.placement`, metres) from a
fixed ~11 m offset. Placement origin, not geometric centroid: no tessellation in extraction; long elements
(beams, walls) are framed from their start point. Revisions ingested before 0005 fall back to an overview. Built on IfcOpenShell's
`bcf-client` 0.9.0 (xsdata models generated from the official XSDs), pinned directly. Output validated
against the buildingSMART BCF-XML release_3_0 XSDs (not vendored: licence NOASSERTION). Not yet opened
in a real viewer (PLAN.md §2 item 8 asks for that).

## D-26 · Copilot query limit
`/copilot/query` allows one question in flight and 10 started per 60 s; beyond that 429 `copilot_busy`.
Each question is a multi-call tool loop billed to the key owner (or burning the free tier's 50/day), so
this caps spend from a stuck client or a script. In-process (`services.copilot.Limiter`, threading lock +
deque): the API runs one uvicorn worker. Several workers or a shared deployment need a shared limiter
(Redis) plus auth (D-24). The rest of the API stays unlimited: reads are local, uploads are size-capped.

## D-27 · SPA Content-Security-Policy in nginx (2026-11-10)
nginx sends a same-origin CSP on every response: `script-src 'self' 'wasm-unsafe-eval'` (web-ifc compiles
wasm), `worker-src 'self' blob:`, `style-src 'self' 'unsafe-inline'` (React style props, the HTML report's
`<style>`), `connect-src 'self' blob: data:`, `object-src 'none'`, `frame-ancestors 'none'`. No inline scripts
anywhere, so no nonces. Found while testing: nginx's mime.types has no `.mjs`, so `/fragments-worker.mjs`
went out as `application/octet-stream` and, with `nosniff`, the browser refused the module worker and the
viewer hung on "Preparing 3D model". A `location ~ \.mjs$` with `default_type text/javascript` fixes it.
Browsers that cached the old response need one hard reload.

## D-28 · IFC 4.3 infrastructure models (2026-11-10)
Found by auditing the buildingSMART Chesapeake Bay Bridge-Tunnel sample (IFC4X3, 25 km, 17.5k elements).
(1) Files declare `FILE_SCHEMA(('IFC4X3'))` but ifcopenshell registers `IFC4X3_ADD2`, so every subclass check
raised and element rules were skipped silently. `engine._schema` resolves a release name to its newest
registered addendum. (2) Infrastructure has no storeys: SPA-001 v2 checks containment in any IfcFacility
/ facility part when the model has no IfcBuildingStorey, and is not_evaluated only when it has neither.
(3) Viewer: ThatOpen's camera caps orbit distance at 300 m and the far plane clipped km-scale models, so the
corridor rendered empty. `fit()` grows `maxDistance` and `far` (near = far / 1e5) to the model's bounding sphere.
IfcSpace volumes are hidden in 3D (they covered the elements inside and are not elements; picks 404'd).

## D-29 · ArchiCAD composites and rule-version changes across revisions (2026-11-10)
Found by auditing buildingSMART Schependomlaan (ArchiCAD IFC2X3): 705 findings, about 600 of them false.
(1) QTO-002 v2 compares Qto `NetVolume` first and falls back to `GrossVolume`. The tessellated geometry has
openings cut, so Gross differed by up to the opening volume on every wall that had a window.
(2) MET-001 / CLS-001 v2: an `IfcBuildingElementPart` aggregated into a parent element is not_applicable,
because name and classification belong to the parent (ArchiCAD layer parts are unnamed by design).
(3) `IfcVirtualElement` is not extracted. Like opening elements, it is an imaginary boundary, not a building
element (it raised SPA-001 containment findings). Schependomlaan result: 705 → 71 findings, MHI 98.4 → 99.7.
(4) A comparison across audits where a rule's version differs (`summary.rules[].version`) marks that rule's
new/resolved/changed events `uncertain`, note `rule_version_changed`. Without this, CLS-001 v1→v2 showed as
model fixes. An identical finding under both versions stays `persistent`; a finding on a removed element stays
`resolved` (`element_removed`). Clinic r1→r2 across CLS-001 v1→v2: 50 resolved (all element_removed), 4202 persistent.

## D-30 · Geometry volume cache; UI localization EN/RU (2026-11-10)
(1) A geometry audit writes `files/{sha}.volumes.json` beside the content-addressed IFC. The quantities API
reads that cache and returns `method=geometry` rows; it never computes geometry in a request (D: IFC work
stays in the job runner). The cache is keyed by file hash, so it cannot go stale.
(2) The UI is localized without a library. The English string is the key, `i18n-ru.ts` maps it to Russian,
and a missing key falls back to English. Backend tokens (statuses, events, dimensions, notes) are translated
for display only; API values stay English. `i18n.test.ts` fails on any `t("...")` key without a Russian
entry, or on a translation that drops a `{placeholder}`. Rule messages, HTML/BCF reports and copilot tool
data remain English; the copilot answers in the language of the question.

  report labels at render time (`axiom/i18n.py`). Stored findings, JSON reports and tokens stay English, so

## D-32 · Issue triage on findings (2026-11-10)
- Triage lives in table `issues`, keyed by `(model_id, identity_key)`. Identity is model-scoped and stable across
  revisions, so state, assignee, due date and note carry over to the next revision of the same finding.
- States are `open|in_progress|disputed|accepted|closed`, a third vocabulary separate from check statuses and
  revision events. A finding with no row is `open`. "Overdue" is derived (due date passed, state not accepted/closed),
  never stored.
- `PUT /models/{id}/issues` is a partial bulk upsert (up to 20000 keys): only the fields sent change, `null` clears.
  The Quality Center applies it to whatever the filters show, so "per rule" grouping is the rule filter, not a new entity.
- No users or auth yet: assignee is free text. Replace with a user id when accounts arrive.

## D-33 · Project dashboard (2026-11-10)
- `GET /projects/{id}/dashboard` returns, per model, the MHI of each audited revision (latest audit per revision)
  and, over every model's latest audit, issue counts: states, overdue, unassigned, active by assignee and by rule.
  Computed in the backend from stored audits plus the `issues` table; the UI only draws it.
- "Active" = open, in progress or disputed. Overdue uses the server's date. The trend uses a fixed 0-100 axis so
  models and revisions compare honestly; a score of `null` (blocked or nothing evaluated) is left out of the line.

## D-34 · Project IDS library (2026-11-10)
- `project_ids` keeps the client's requirement files per project (name, `ids_hash`, `is_default`); the file itself
  stays content-addressed in `files/{sha}.ids`. The same file twice returns the existing entry; the first entry is the
  default; at most one default per project.
- The revision upload stays explicit: it takes an `ids_hash` or nothing. The default only preselects the choice in the
  upload form, so a CLI or API upload never picks up requirements silently.

## D-36 Acceptance gate (2026-11-11)

Closes the core of audit gap G1: an audit now yields a delivery decision, not only a score.

- **Vocabulary.** `accepted | accepted_with_comments | rejected | undecided`. Separate from finding statuses and
  revision events; never mixed.
- **Rule** (`score/gate.py`, pure). An open finding is a `fail` or `warning` whose issue state is not `accepted`
  (the reviewer's waiver). `rejected` when an open `fail` is at or above the project's blocking severity, or the
  MHI is below the project minimum. Otherwise `undecided` when the MHI was not computed or (policy) no IDS was
  checked: a delivery is never accepted on something that was not evaluated. Otherwise
  `accepted_with_comments` when anything was raised (waived findings count as comments), else `accepted`.
- **Policy per project**: `min_score` (80), `block_severity` (`critical`), `require_ids` (true); three columns on
  `projects` (migration 0008). `GET/PUT /projects/{id}/gate-policy`.
- **Computed at read time** (`GET /audits/{id}/gate`) from stored findings, current triage and current policy, so
  a waiver shows at once. Consequence: the decision is not frozen; the report prints the policy it used.
- **Reasons are machine codes** (`blocking_findings`, `score_below_minimum`, `ids_not_evaluated`,
  `score_not_evaluated`, `open_findings`, `waived`); UI and report phrase them. The report opens with the decision.
- Not built: per-stage policies, a signed/frozen certificate, a project-level gate over several models,
  the decision on the revisions timeline and in the CLI.

## D-37 Quantities CSV, IDS version diff, and why there is no duplicate-element rule yet (2026-11-11)

- **Quantities CSV (G6).** `GET /revisions/{id}/quantities?format=csv` (same `by` and `against`): one line per
  group / quantity / method with unit, total, element count, missing count, previous total and change. UTF-8 with
  a BOM so Excel reads Cyrillic names. Formatting only (`quantities/export.py`); numbers come from `aggregate`.
  A group that only the previous revision had keeps a line with an empty total. No .xlsx: CSV opens in Excel
  and needs no dependency.
- **IDS version diff (F3).** `GET /projects/{id}/ids/{entry}/diff?against={older}` lists specifications added,
  removed, changed (with the part that differs: applicability, requirements, name, ...) and the unchanged count.
  Specifications match by `identifier`, else by name, so a renamed identifier reads as removed + added.
  It does not say which facet inside a part changed.
- **Duplicate-element rule (G7): tried, not shipped.** A rule on class + placement origin + type + quantities
  flagged valid elements in the clean fixture: two walls or beams that start at the same corner share an
  origin and differ only in rotation. A sound rule needs the world bounding box from the geometry pass
  (`quantities/geometry.py`), not the snapshot. A noisy rule would cost more trust than it adds.

## D-38 — Gate decision on the timeline and in the CLI; quantity delta against a chosen revision (2026-11-11)

- **Revisions list carries `decision`** (same `gate.for_audit` as the Quality Center, latest audit of each
  revision; `null` when never audited). The timeline shows it per row.
- **`axiom audit` prints the delivery decision and its reason codes; `--gate` exits 1 unless the decision is
  `accepted` or `accepted_with_comments`.** `undecided` fails the gate too: a delivery that was not checked
  against the client's IDS has not passed. Same service as the API, so designer and client see one result.
- **Quantities "Compare with".** The page picks any earlier revision (`?against=`), default the previous one;
  each option names that revision's decision. No "last accepted" shortcut is computed: the decision is read
  at request time from the current policy and waivers, so it is shown, not frozen.

## D-39 — Project coordination: project decision and cross-model checks (2026-11-11)

- `GET /projects/{id}/coordination` takes the latest revision of every model in the project.
- **Project decision = worst model decision** (accepted < with comments < undecided < rejected). A model with
  no audited delivery makes the project `undecided`: an absent discipline is not a passed one.
- **Checks** (`axiom/coordination.py`, pure, snapshot facts only):
  - `length_unit` — same LENGTHUNIT in every model, else `fail`.
  - `georeferencing` — same IfcMapConversion / site reference in every model; a model without one next to a
    georeferenced model is a `fail`; nobody georeferenced is `not_evaluated`.
  - `storey_elevations` — each model's levels must exist in the others within 10 mm. A mismatch is a
    `warning`, not a fail: a structural model may legitimately carry a foundation level. `actual` lists only
    the unmatched levels per model.
  - Fewer than two models with the fact → `not_evaluated`, never `pass`.
- Not done: origin offset between models (needs shared reference points from the geometry pass); choosing
  which revision of each model forms the delivery set.

## D-40 — Issue digest per assignee (2026-11-11)

  each issue as model · rule · element (class, name, GlobalId) · state · due date, overdue items first;

## D-41 — Issue change history (2026-11-11)

- New table `issue_events` (migration 0009): one row per field an update actually changed — field, old, new,
  author, time. A bulk update over N findings writes one row per finding and changed field. Setting a field
  to the value it already has writes nothing.
- A new issue starts from `state = open` and empty fields, so the first change reads "open → disputed".
- `author` is the name the user typed (kept in the browser's localStorage, sent with every update). It is
  **not verified**: there is no login yet (G11). The history says who *claimed* to make a change; real
  accountability needs users.
- `GET /models/{id}/issues/{identity_key}/history`, oldest first. The issue editor loads it only when
  "History" is opened.
- BCF export does not include the history yet.

## D-42 — Frozen acceptance certificate (2026-11-11)

- The live gate (D-36) is recomputed on every read, so a policy or waiver change rewrites history. A
  certificate freezes it: `POST /audits/{id}/certificates` stores decision, reasons, policy, MHI score,
  project/model/revision, file SHA-256, ruleset version, IDS hash, engine version, scoring config, audit time,
  issue time and issuer name in table `certificates` (migration 0010). Rows are never updated.
- `sha256` is computed over canonical JSON of the payload (sorted keys, no whitespace). `GET` recomputes it and
  returns `valid: false` if the stored payload was edited in the database afterwards.
- This is a tamper-evidence hash, **not a signature**: there is no key and the issuer name is typed, not
  verified (same limit as D-41). Signing needs users (G11). No PDF yet; the browser's print of the report is
  the paper copy.
- The Quality Center gate panel has "Issue certificate" (uses the name entered for issue history) and shows
  the latest one with its short hash.
