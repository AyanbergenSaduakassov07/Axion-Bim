# Decisions (ADR log)

Append-only. One entry per decision: context → decision → consequence. Supersede, don't edit.

## D-01 Library + CLI before API/UI
Engine is `src/axiom`, exercised first through `axiom` CLI. API and web call the same `services/`. Consequence: every feature is testable without HTTP or a browser; demo exists from M1.

## D-02 Python 3.12, uv, one package
ifcopenshell 0.9.0 supports 3.10–3.15; 3.12 is the safe wheel target. One package `axiom` with modules; no workspace until a second consumer exists.

## D-03 Revision diff = snapshot diff
Diff normalized snapshots by GlobalId (added / removed / modified, property-level paths like `pset:Pset_ColumnCommon.LoadBearing`). IfcDiff (0.9.0) is optional cross-check and geometry-change signal only. Consequence: fast, deterministic, granularity matches findings.

## D-04 IDS for information requirements; Python rules for the rest
IfcTester 0.9.0 evaluates IDS. Custom rules are Python functions registered with metadata (id, version, name, category, severity, dimension, applicability, issue_key). No YAML DSL. Rule parameters (thresholds) may live in a small YAML per rule set. Both produce `Finding`.

## D-05 SQLite via SQLAlchemy Core + Alembic
Postgres later is a URL change. JSON columns only for evidence/metadata. All queries parameterized; repo layer only, called from services only.

## D-06 Subprocess job runner, no Redis
Jobs table in SQLite; runner spawns a child process per job with timeout and memory limit (`resource.setrlimit` on POSIX). Reason: isolate native crashes, not scale. Swap to RQ/arq only when concurrency demands it.

## D-07 Fixtures generated by code
`tests/fixtures/factory.py` builds IFC4 models with `ifcopenshell.api`, each with an `expected.yaml`. Public models only for benchmarks; record license + source in `examples/models/SOURCES.md`.

## D-08 Viewer: ThatOpen components 3.x (pending P00)
Pin `@thatopen/components`, `components-front`, `fragments` at the versions P00 validates (3.6.x as of 2026-11-09), `web-ifc` 0.0.77 (see D-11). Backend stays the source of truth; viewer only renders and maps GlobalId ↔ local id. Fallback if P00 fails: xeokit-sdk (AGPL — check license impact) or web-ifc + three.js direct.

## D-09 Copilot: read-only tools over services, citation post-check
Claude tool-use; tools wrap service functions, never raw SQL. Every GlobalId / finding id in the final answer must appear in that turn's tool results, else reject. Source IFC never sent to the LLM.

## D-10 Reports: JSON canonical, HTML rendered, PDF = browser print
Every report embeds reproducibility block: file sha256, ruleset hash, IDS hash, engine + app version, scoring config, timestamp.

## D-11 Viewer pins validated (amends D-08) — 2026-11-09
P00 GO for ThatOpen. Pins: three 0.182.0, @thatopen/components 3.6.0, @thatopen/fragments 3.6.1, **web-ifc 0.0.77** (0.0.78 incompatible with fragments 3.6.1). WASM + fragments worker served from our own origin. Element table stores `step_id` (== viewer localId) alongside GlobalId to disambiguate duplicate GlobalIds.

## D-12 New candidate rule QTO-002 + IDS coverage hints — 2026-11-09
From P00: Revit-exported Qto values can be off by unit factors (slab GrossVolume ×1000). Add QTO-002 (Qto vs geometry/declared-dimension plausibility) in P07. IDS adapter reports subtype coverage gaps (exact-class entity facet) and maps zero-applicable specs to `not_applicable`.

## D-13 Snapshot storage details — 2026-11-09
Property values stored typed (`value_type` + `value_text`/`value_num`), not JSON, so rules and SQL compare natively; `load_snapshot(ingest(x)) == extract(x)` is a test invariant. Revisions are unique per (model, file sha256) and numbered `seq` per model. Openings/voids (IfcFeatureElementSubtraction) are excluded from elements. Profile treats material as expected only on primary structural classes; rule sets own the real applicability (P03).

## D-14 IDS adapter mapping — 2026-11-09
- One IDS spec = one rule `IDS:<identifier or name>`, version = IDS file sha256[:12]; counts are per (applicable entity, requirement facet). Duplicate ids get `#<spec index>`.
- Status: spec for another schema -> `not_applicable` (`should_filter_version=True`); unevaluated -> `not_evaluated`; zero applicable -> `fail` if required (minOccurs>0) else `not_applicable`; prohibited (maxOccurs=0) -> one `fail` per matching entity.
- Severity per requirement facet: `optional` cardinality -> medium, else high. Coverage gaps (exact-class entity facet skipping subtypes, e.g. IfcWallStandardCase) -> `warning`/`info`, issue_key `<i>/coverage/subtypes`.
- IfcTester 0.9.0 drops spec `@identifier`; `load_ids` decodes once and restores it. It also fails the suite case "optional attribute passes if null"; we report its verdict unchanged and track it as a strict xfail.
- IDS files stored content-addressed next to IFCs (`files/<sha256>.ids`), hash in `audit_runs.ids_hash`. `ruleset_version` still identifies built-in rules only.
- Conformance subset: 13 buildingSMART IDS test cases vendored unmodified (CC BY-ND 4.0, attribution in NOTICE).

## D-15 MHI v1 scoring details — 2026-11-09
- Config `src/axiom/score/config/default.yaml` (versioned; stored per audit in `audit_runs.scoring_config_json`, version in the reproducibility block). Rule→dimension by fnmatch pattern, first match wins; unmapped rules are noted, not scored.
- `s_i = pass/(pass+fail)`. `warning` counts as evaluated for coverage but not in the score, so a model without classification gets a null `classification_quality` (noted, weight redistributed) rather than a fail. `not_applicable` is neither score nor coverage gap.
- Coverage = (pass+fail+warning)/(that + not_evaluated + error). IDS subtype coverage gaps (D-14) add one `not_evaluated` per skipped entity, so coverage drops instead of hiding them.
- Score rounded to 6 dp (float-sum noise); null when no dimension evaluated. Critical gate = any `critical` `fail` finding → `blocked`, identity keys listed.
- MET-001 (naming) and QTO-001 feed `property_completeness`; GEO-002 feeds `model_consistency`.

## D-16 · Revision engine details (P06)
- Diff matches by GlobalId; duplicated GlobalIds in either snapshot are excluded and listed as uncertain. Quantities compare on `si_value` with `QUANTITY_REL_TOL=1e-6`, so a unit change alone is no change. Removed property → `new=None`.
- `identity_unstable` when removed AND added both exceed 50% of a class in the base; then every event is `uncertain`.
- History = latest audit of every audited revision of the model up to base (by seq). `changed` = same identity key, different status/severity/actual/evidence.
- A rule run on only one side (e.g. IDS used in one audit) cannot resolve or introduce findings: its events are `uncertain` with note `rule_not_evaluated_in_base|head`. Ruleset/IDS hash mismatch is flagged in `comparisons.summary_json`.
- Impact = non-persistent events on elements that also changed, with the change paths. Not done: "rules whose applicability covers the changed element" (needs applicability introspection), `--ifcdiff` cross-check (optional).
- `axiom audit` auto-compares with the previous revision of the same `--model`; the default model name is the file stem, so differently named files are separate models unless `--model` is given.

## D-17 · Quantity intelligence details (P07)
- Totals keyed by (group, qto, quantity, method): two Qto sets never double-count and `qto`/`geometry` values are never summed (`method` is part of the row key; tested). Units are SI labels (m, m2, m3, kg) since `si_value` is already scaled at extraction.
- `missing` = GlobalIds in the group whose class carries that quantity elsewhere in the group but has no value; never treated as zero.
- `--geometry` computes volumes for every element (not only those lacking Qto) via `ifcopenshell.geom.iterator` + `util.shape.get_volume`, so Qto and geometry columns can be compared. Geometry area left out: the shape footprint is in local coordinates and would mislead.
- QTO-002 (D-12) = Qto Gross/NetVolume vs geometry volume, fail outside x2, hint when the ratio is ~1e3/1e6/1e9. Opt-in (`run_audit(geometry=True)`, `axiom audit --geometry`), recorded as `reproducibility.geometry`. Finds both x1000 slabs in the Revit sample. Comparing a geometry audit with a non-geometry one gives `uncertain` QTO-002 events (D-16).
- Revision deltas: `services.quantities.delta(base, head)` on grouped totals; not yet folded into `comparisons.summary_json` (P11 can call it).
